# Terminal fidelity and feature audit

Research date: **19 October 2026**. Baseline: **Armin Terminal 2.9.0**, commit `7d1d2d9`, with 72 registered functions. The conclusions below come from the command registry, implementation and provider documentation, plus the public Bloomberg sources linked beside the comparisons. This is a source and workflow review; it is not a comparison against a running licensed Bloomberg session.

The project already has a substantial local terminal: per-panel commands, security-qualified identifiers, familiar mnemonic aliases, numbered actions, related-function menus, six-panel layouts, colored security linking, chart studies, public-source research and several useful calculation models. The largest remaining gap is the underlying information and connected workflow, followed by consistent screen and keyboard behavior. Matching all of Bloomberg cannot be established from public documentation, and an identical-looking screen would not create its datasets, contributor network, research, execution services or entitlements.

## What the public references actually establish

Bloomberg's [getting-started guide](https://data.bloomberglp.com/professional/sites/10/Getting-Started-Guide-for-Students-English.pdf) provides a useful, dated convention reference. Printed pages 2, 5–12 and 13 describe:

| Convention | Reference location |
| --- | --- |
| Red stop, green action and yellow sector keys; Enter executes | p. 2 |
| Independent panels with toolbar, command line and function area | p. 5 |
| Persistent loaded security, mnemonic commands and security-specific functions | pp. 6–8 |
| Autocomplete and related-function menu hierarchy | pp. 9–12 |
| Red function menu bar, amber editable fields, white hover outlines and numbered actions | p. 13 |

These conventions inform the recommended presentation. They do not define exact RGB values, fonts, every contemporary screen, or a complete function specification. Treat the app's palette and spacing as design choices, not certified Bloomberg measurements. Preserve keyboard focus, legibility and source labels when applying them.

Bloomberg's current [Terminal overview](https://professional.bloomberg.com/products/bloomberg-terminal/) also describes research, communication, cross-asset analysis, mobile access and execution. Those are separate capabilities; a count of local commands is not a percentage of Terminal coverage.

## Capability assessment

**Implemented** means the named local behavior exists. **Partial** means a usable subset exists with narrower coverage. **Model** means a calculation under stated assumptions. **Missing** means no equivalent implementation. **Service dependent** identifies work that also needs suitable external data, entitlements or counterparties; writing a UI alone cannot complete it. Several rows deliberately carry more than one classification.

| Area | Baseline assessment | Concrete evidence and remaining work |
| --- | --- | --- |
| Command-driven navigation | Implemented, partial | `commands.ts`, `exec.ts` and `registry.ts` support security-first/function-first commands, aliases, class restrictions, contextual menus and numeric actions. A familiar mnemonic executes this app's function. Error handling, focus, cancellation and menu semantics must remain consistent across panels. |
| Desktop/workspace | Implemented, partial | `state.ts`, `TopBar.tsx`, `Panel.tsx` and `linked-workspaces.md` cover local layouts, history and security groups. Cross-window linking, account synchronization, a general component catalogue and collaboration are absent. |
| Security identification | Partial, service dependent | `data/registry.ts` resolves local tickers and aliases; online equity lookup handles US stocks and fifteen European exchanges. This is not a universal instrument master. `Mtge`, `M-Mkt`, `Muni` and `Pfd` have no securities in the registry. Comprehensive ISIN/CUSIP/FIGI resolution, issuer hierarchy, exchange-specific terms and corporate actions remain gaps. |
| Quote, tape and depth | Partial, service dependent | `QUOTE` uses public-source quotes and optional IEX-only snapshots. `TRADES` derives rows from source updates; these are not individual audited exchange prints. `DEPTH` has a Kraken crypto book and best bid/offer elsewhere. Consolidated real-time US prices, NBBO, stock/futures depth and a complete trade tape are absent. |
| Equity research | Partial, service dependent | Reported statements, ownership snapshots, officers, dividends/splits, short interest and provider-labelled analyst sections exist. FMP/Finnhub/Yahoo/Equibles and optional TipRanks have different coverage and account limits. No globally standardized history, full contributor estimates/revisions, comprehensive actions, broker-document library or transcript service is implemented. |
| Screening and relative value | Partial | `SCREEN`, `MOVERS`, `HEATMAP`, `PEERS` and `CONTRIB` work on the available local/loaded universe. They do not scan a complete global market. Most index-contribution measures are local-universe proxies; the Dow is the exception with point contribution. Saved field expressions, point-in-time screening and complete constituent histories are absent. |
| Charts and historical analysis | Implemented models, partial | OHLC charts, several studies, comparisons, history tables, realized volatility, regression and correlation exist. Field-based charting, saved analytic templates, drawing tools, event overlays and consistent export are opportunities. No complete tick archive, observed implied-volatility cube or global total-return adjustment engine exists. Bloomberg separately documents [chart sharing, templates and broader analytic workflows](https://professional.bloomberg.com/products/bloomberg-terminal/charts/). |
| News and research | Partial, service dependent | Official announcements and external provider headlines/links exist; `TOP` opens `MARKETNEWS`. This does not supply Bloomberg reporting or editorial selection. Full-text archive search, research permissions, transcripts and integrated research management are absent. Bloomberg's [news](https://professional.bloomberg.com/products/bloomberg-terminal/news/) and [research](https://professional.bloomberg.com/products/bloomberg-terminal/research/) descriptions substantiate those wider product areas. |
| Economic releases | Partial, service dependent | Official/FRED actuals, prior values, dates and some first-release vintages are connected. Reliable release timestamps, full global coverage, survey consensus, contributor forecasts and historical surprises are missing. Bloomberg describes [consensus and contributor forecasts and release analysis](https://professional.bloomberg.com/products/bloomberg-terminal/research/economics/); actuals alone do not implement that workflow. |
| Fixed income and credit | Models plus missing datasets; service dependent | `BONDCALC` supports regular bullet terms, five day counts, price/yield/risk and manual G/Z-spreads. `BONDS`/`CURVE` show selected published government yields. `BONDSEARCH`, `DEBTPROFILE` and `DEALERQUOTES` have no connected real issue/dealer dataset. Calls/puts/OAS, irregular schedules, credit/CDS, inflation/floating bonds, MBS and municipal-specific workflows are absent. |
| FX, rates and futures | Partial and models; service dependent | Derived currency crosses, front futures, simple-rate forwards, Garman–Kohlhagen FX options, Fed-futures expectations and a manual fixed/float swap model exist. Executable dealer prices, forward basis/smiles, full futures curves/rolls, settlement calendars, past fixings, OIS compounding and collateral/XVA remain gaps. |
| Listed options | Partial and models; service dependent | `OPTIONS` requests Alpaca indicative US-equity snapshots, with distinct trade/quote times and partial pagination. The calculators add European/American single-option analytics and common-expiry strategy analysis. They do not provide OPRA real time, index chains, open interest/daily volume, a fitted market surface, discrete-dividend exercise, assignment, margin or execution. |
| Portfolio | Partial and models; service dependent | Manual holdings/cash, five base currencies, entry-FX metadata, exact-date historical shocks, VaR/ES, signed risk contributions, benchmark tracking error and stress exist. A transaction ledger, reconciled corporate actions, realized performance, factor attribution/optimization and derivative positions are absent. Bloomberg's [PORT description](https://professional.bloomberg.com/products/bloomberg-terminal/portfolio-analytics/) covers institutional risk, attribution and connected data workflows beyond this holdings model. |
| Alerts and notes | Implemented local tools, partial | Price/change/announcement alerts require an open process; notes are local. Background alert delivery, shared research, server state, mobile delivery and firm retention controls are absent. |
| Messaging and support | Local bot; service dependent | `MESSAGES`/`IB` responds through `botReply`; there is no human chat network or message transport. Bloomberg's [collaboration tools](https://professional.bloomberg.com/products/bloomberg-terminal/collaboration-tools/) and [live support](https://professional.bloomberg.com/support/customer-support/) are external services. Preserve the visible bot disclosure in both desktop and demo modes. |
| Spreadsheet/programming integration | Missing, service dependent | CSV is available on several screens. It is not an Excel add-in or Bloomberg-compatible BDP/BDH/BDS/BQL/BLPAPI. Bloomberg's [API/BQL Excel session](https://www.bloomberg.com/professional/insights/webinar/bloomberg-data-in-excel-api-bql-webinar/) documents a spreadsheet/query workflow. A future local query API should use its own contract and explicit provider limits. |
| Trading, order management and compliance | Missing, service dependent | No broker/order-routing, confirmations, allocation, transaction-cost analysis or compliance archive is implemented. Bloomberg's [execution management products](https://professional.bloomberg.com/products/trading/execution-management-system/) include connected pre- and post-trade workflows. Adding an `EMSX` alias would not supply them. |
| Current AI workflows | Missing, service dependent | The local help bot has fixed replies and no Bloomberg-grounded retrieval. The current [Terminal overview](https://professional.bloomberg.com/products/bloomberg-terminal/) describes ASKB. Do not rename the bot or imply equivalent data access, citations or analysis. |

## Mnemonics that deserve particular care

| Entry | What this application does | Fidelity consequence |
| --- | --- | --- |
| `FLDS` | Inspects 29 currently held local fields | Useful provenance tool; no Bloomberg field contract, history request or query-language compatibility. |
| `TAS` | Displays aggregated source updates or observed IEX snapshots | Do not call the rows a complete exchange tape or infer unprovided conditions/venues. |
| `IB` / toolbar `MSG` | Opens a local rule-based help bot | The toolbar label can imply a communications feature. Prefer an explicit local-help label; do not suggest delivery to people. |
| `SRCH`, `DDIS`, `ALLQ` | Opens screens unavailable for real issue/dealer datasets | Display the unavailable state before any demonstration figures and keep demo data unmistakable. |
| `YAS`, `SWPM`, `OVME`, `OVML`, `PORT` | Runs the documented subset/model | Preserve assumptions and provenance in-screen and in CSV; a familiar name cannot imply all instrument conventions or institutional analytics. |
| `LPAD` | Opens local saved layouts | Bloomberg's hosted [2018 primer](https://data.bloomberglp.com/professional/sites/10/LUISS_2018Primer.pdf) distinguishes `BLP` (workspace) from `LLP` (current function into Launchpad). A local compatibility entry must implement an appropriate local action and explain its scope. |
| `EE` | Combines reported earnings, provider comparisons and some annual estimates | This is not a complete quarterly estimate/contributor/revisions workflow. Keep reported and estimated figures, reporting basis and fiscal periods distinct. |

## Recommended implementation order

This order is an engineering assessment of user impact and feasibility, not a claim that Bloomberg publishes this roadmap.

1. **Make the shared shell coherent.** Use the documented function-bar/input/action conventions consistently. Keep the loaded security, primary mnemonic, active panel, keyboard focus and data status visible. Apply shared styles to charts, research and calculators; verify that higher density does not clip controls at 1280×800, four-panel and narrow layouts. This benefits every function without requiring another dataset.
2. **Complete the everyday keyboard loop.** Verify security → description → financials → chart → company news → contextual help → menu/back, including linked-panel changes. Make cancellation and editor focus predictable. Add familiar workspace entry points only where their local behavior is faithful; avoid silently redirecting unsupported functions.
3. **Turn watchlists into useful local worksheets.** Add persistent column selection from actual available fields, sort/filter state, column units, missing-data reasons and CSV. Reuse the field catalogue and source metadata. Do not issue provider requests for every column or invent values for missing fundamentals. Bloomberg distinguishes [Worksheets and Launchpad](https://www.bloomberg.com/professional/insights/technology/bloomberg-terminal-essentials-ib-worksheets-launchpad/); one fixed quote list covers only a small subset.
4. **Finish calendars before extending valuation scope.** The bond settlement helper currently skips weekends only. Add explicit, tested settlement calendars and holiday-roll conventions, then consider irregular coupons and discrete dividends with independent numerical references. Continue to distinguish published par yields from zero curves. Add no new asset-class label until the contract and calculation are supported.
5. **Make research continuity robust.** Retain security and fiscal context across profile, earnings, statements, filings, analysts and charts. A saved chart configuration or event overlay offers more everyday value than another unavailable mnemonic. Show loaded-universe counts on screening and rankings so the user can judge the result's scope.
6. **Add a real portfolio ledger before return attribution.** Record dated trades, fees, cash movements, FX and corporate actions; derive reproducible positions/performance from it. The current fixed-quantity historical replay should remain explicitly hypothetical. Only then build allocation/selection attribution, factor risk and derivative exposure.
7. **Connect and verify permitted datasets.** Prioritize consolidated quotes/tape, fuller identifiers/actions, economic consensus, complete estimate history and individual bond reference/prices according to the intended desk workflow. Each source needs real account/endpoint checks, coverage examples, timestamp semantics, adjustment conventions and failure behavior. Existing provider fixture tests cannot establish live entitlement.
8. **Treat network and enterprise functions as separate integrations.** Human communications, remote alerting, broker execution, spreadsheet APIs, multi-user state and research permissions need service design and working counterparties. Keep them outside any claim of an exact replica until actually connected and validated.

## Acceptance criteria for a credible next release

- A screenshot can show presentation improvements, but coverage claims must be traceable to a registered implementation, dataset and verification record.
- Compare fixed workflows, resolutions, securities, dates, currencies and adjustment conventions. A later live price is not a useful numeric reference for an earlier snapshot.
- For each changed calculation, retain explicit inputs and independent expected outputs. Include empty, stale, partial and not-entitled states in workflow checks where relevant.
- Open every registered function in both no-key and demonstration modes; check that unavailable real datasets cannot look populated. Exercise an entitled live source separately where credentials are actually available.
- Verify keyboard and pointer paths on the same screen. A numbered action must execute the same action that its button advertises, without stealing focus from an editor.
- Persist the workspace, reload it, switch the linked security and confirm each compatible panel retains its function and correct security-specific inputs.
- Publish remaining limitations beside the result. No running licensed reference session was available for this audit, so exact visual, dataset, numerical and service parity remains unverified.
